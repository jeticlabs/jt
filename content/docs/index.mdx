## What Jetic does

Traditional API testing tools force you to hand-write repetitive request scripts, hardcode authorization tokens, and guess what your handlers actually validate. Jetic starts from your code instead:

1. **Static source scanning** — parses your project with `ts-morph` (no server boot) to discover routes, path parameters, nested routers, and recognizable middleware.
2. **Behavioral model** — writes a versioned, strongly-typed graph of your API into [`.jetic/model.json`](/docs/reference/artifacts), including exact source provenance (file + line).
3. **Stateful workflows** — executes multi-step journeys from [`.jetic/workflows/*.json`](/docs/guides/workflows) with dynamic capture and header injection.
4. **Simulation & traces** — runs your journeys against a live server and renders every step as an interactive graph in [Jetic Studio](/docs/guides/jetic-studio).

<Callout title="No AI key required">
Jetic does not need an OpenRouter/OpenAI account. The static scanner is keyless, and when you connect Jetic to your code editor over [MCP](/docs/guides/ai-ide-mcp) your editor's own model drives the same tools.
</Callout>

## The four primitives

Everything in Jetic revolves around four objects:

| Primitive | Answers | Artifact |
| :--- | :--- | :--- |
| **Model** | *What exists?* | `.jetic/model.json` |
| **Workflow** | *What happens?* | `.jetic/workflows/*.json` |
| **Memory** | *What carries between steps?* | `.jetic/memory.json` |
| **Trace** | *What actually ran?* | Jetic Studio `/traces` |

## The 4-phase lifecycle

Jetic operates on a strict, predictable lifecycle so the model stays faithful to your code:

| Phase | Command / tool | Purpose |
| :--- | :--- | :--- |
| 1. Initialize | `jetic init` | Scaffold `.jetic/` and an empty model |
| 2. Scan & model | `jetic scan` | Discover endpoints from source |
| 3. Verify | `jetic_verify_model` | Validate completeness and structure |
| 4. Simulate | `jetic simulate workflow` | Execute stateful journeys |
